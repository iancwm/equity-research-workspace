# Equity Research Workspace

A persistent, modular equity-research system for producing institutional-quality initiation of coverage (IOC), updates, scenario work, and monitoring dashboards without discarding the research state after each report.

## Design principle

The report is an output, not the research database.

Each covered company keeps persistent state under `companies/<ticker>/`:

- sourced evidence and provenance;
- normalized facts;
- assumptions and scenarios;
- analytical conclusions and falsification criteria;
- dependency mappings;
- reusable financial/valuation data;
- editable generated outputs.

A new report should reuse this state and recompute only what changed.

## Core workflow

```text
User request
   ↓
Target + research question
   ↓
Quick framing / research plan
   ↓
Source ingestion → source registry
   ↓
Evidence normalization → research ledger
   ↓
Analytical modules → ledger updates
   ↓
Company overlay / forecasts
   ↓
Valuation & expectations
   ↓
Strategist dashboard
   ↓
Synthesis
   ↓
Independent QA
   ↓
IOC / update / scenario output
```

Later modules receive the relevant ledger state, assumptions, and required evidence—not every word generated by earlier modules.

## Start here

1. Read `SKILL.md`.
2. Create a company workspace with `python scripts/init_company.py ACN "Accenture plc"`.
3. Fill or infer `companies/ACN/project.yaml` and `state/research-context.yaml`.
4. Choose a workflow from `workflows/`.
5. Use `scripts/validate_workspace.py companies/ACN` before publication.

## Recommended modes

- **Quick View:** fast initial thesis and research questions; minimal persistence required.
- **Full Initiation:** complete research state + IOC.
- **Update:** ingest new evidence and selectively recompute affected nodes.
- **Scenario:** alter assumptions without unnecessary web research.
- **Publish:** turn validated state into Markdown, document, spreadsheet, or presentation outputs.

## Why this structure exists

It fixes four common failures of one-shot AI research:

1. long latency before the user gets any useful signal;
2. inability to edit one section without regenerating everything;
3. loss of source data and assumptions after synthesis;
4. repeated expensive research on subsequent updates.
